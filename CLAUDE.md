## What this repository is

This repository contains the **source of truth** for the ASCENT framework:

- The parent skill `lloydbriantech-ascent` that scaffolds, enhances, and migrates projects
- The reference modules consumed by the skill at runtime
- The template assets shipped to scaffolded projects (with substantive baseline content, not skeletons)
- The framework's own architectural decision records
- The tooling that builds the paired starter repo from the skill
- The test harness that proves the skill produces working projects

The framework is **the framework's first user**. This repository observes ASCENT conventions wherever they apply (make as operator vocabulary, ADR discipline, phase-gated delivery, dual licensing, persona-segmented docs).

## Architecture rules

These are non-negotiable for any change to this repository:

1. **The parent skill is the single source of truth.** The starter repo and any other downstream artifacts are *built* from the skill, never edited directly.
2. **Modify, never overwrite.** When changing skill assets or reference modules, use surgical edits. If a change requires rewriting an entire file, capture the rewrite rationale in an ADR.
3. **Substantive content, not skeletons.** Every template file shipped by ASCENT must contain working, opinionated, productive defaults. A file that says only `// TODO` violates this rule.
4. **No documentation theater.** A doc exists only if someone reads it. Lazy-generated docs are created on demand via `make doc-stub TYPE=<name>`, not eagerly.
5. **Test what you ship.** Every skill mode (scaffold / enhance / migrate) must have at least one eval scenario in `tests/`.
6. **Slug input is one variable.** A user provides one project slug; all derivations (uppercase env-var prefix, title case, package name, container label) are computed mechanically.

## Working conventions

### Commits

- **Conventional Commits** format: `<type>(<scope>): <subject>`
- Types: `feat`, `fix`, `docs`, `refactor`, `test`, `chore`, `build`, `ci`
- Scopes: `skill`, `references`, `template`, `tests`, `tools`, `docs`, `meta`
- Subject in imperative mood, lowercase, no trailing period

Examples:
```
feat(skill): add ai-engineer role module
docs(framework): expand PHILOSOPHY.md with documentation theater anti-pattern
fix(template): correct slug derivation in Makefile placeholder
```

### Branches

- `main` is always shippable (current shipped framework version)
- Feature branches: `feat/<scope>-<description>`
- Fix branches: `fix/<scope>-<description>`
- Doc branches: `docs/<area>`

### ADRs

Any decision that future contributors might wonder about gets an ADR. Use the canonical template:

```markdown
# ADR-NNN: <Title>

**Status:** Proposed | Accepted | Superseded by ADR-XXX
**Date:** YYYY-MM-DD (America/New_York)
**Decider:** lloydbriantech

## Context

What is the issue we're seeing that is motivating this decision?

## Decision

What is the change we're proposing or have agreed to implement?

## Alternatives considered

What other options were on the table? Why were they rejected?

## Consequences

What becomes easier or more difficult as a result? Trade-offs accepted?

## Cost implications

What does this decision cost — in time, money, complexity, or future flexibility?
```

### Phase transitions

A phase ends when its exit criteria (listed in [`docs/framework/ROADMAP.md`](docs/framework/ROADMAP.md)) are all met. To transition:

1. Verify exit criteria via `make phase-check` (Phase 1+)
2. Update `CHANGELOG.md` with the phase summary
3. Tag the release: `git tag v0.N.0 && git push --tags`
4. Wait for explicit signal: **"Proceed with Phase N+1"**
5. Update phase status in this CLAUDE.md and in [`docs/framework/ROADMAP.md`](docs/framework/ROADMAP.md)

No phase begins implicitly. The signal is the gate.

## Make operator vocabulary (Phase 1+)

`make help` is the entry point. Sections in SDLC order:

```
META    — reference (help, version, status)
DEV     — work on the framework locally
TEST    — run eval scenarios against the skill
QA      — validate skill structure, frontmatter, links
DOCS    — generate / audit documentation
DIST    — package the skill, build the starter repo
RELEASE — tag, changelog, publish
```

Phase 0 (this) does not ship a Makefile yet. Phase 1 introduces it.

## What this repository is NOT

- It is not the place to edit `lloydbriantech-ascent-starter` directly. That repo is generated from this one.
- It is not a place for projects scaffolded from ASCENT to live. Each scaffolded project gets its own repository.
- It is not a sandbox for experimental skill ideas — those go on a feature branch and come in via PR.
